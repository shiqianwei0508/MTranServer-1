## Docker 构建缓存失效修复（bun install 每次重跑）
- 症状：`docker build` 时 `RUN bun install --frozen-lockfile` 每次都不走 CACHED，重新安装。
- 根因：`docker/package.json` 的 version 字段每次 bump 版本号时被手动同步（5.0.21→22→23），`COPY docker/package.json` 层源文件哈希变化 → 紧随其后的 `RUN bun install` 层缓存失效 → 每次重装。bun.lock 的 root 条目不记录 version，版本号对依赖解析完全无用。
- 修复：
  - `docker/package.json` version 固定为 `1.0.0`，以后 bump 版本号**不再同步**该字段（已验证 `bun install --lockfile-only --cwd docker` 重写 lock 无 diff，--frozen-lockfile 不受影响）。
  - `docker/Dockerfile` 在 COPY package.json 前加缓存说明注释；`docker/README.md` 构建章节加"构建缓存说明"。
  - 新增 `.gitattributes`：`docker/**` 与 `*.sh` 固定 `text eol=lf`，防止 Windows CRLF 波动再造成 COPY 层哈希变化（服务器 Linux 无此问题）。
- 验证方法：连续两次 `./docker/build.sh`，第二次日志中 install 层应变 `CACHED`。服务器需 git pull 获取该改动。

## 再纠正：offline 模式 OCR 禁止联网下载（未提交）
- 用户进一步要求："offline模式下，应该直接找本地ocr模型，而不是联网下载了吧？"——确认 `model-cache.ts`：缓存文件名 = `path.basename(new URL(url).pathname)`，缓存命中 `existsSync` 直接读、缺失才 `fetchArrayBufferWithRetry` 联网。
