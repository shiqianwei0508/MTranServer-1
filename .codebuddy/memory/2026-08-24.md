## 重要纠正：PP-OCRv6 官方没有 "server" 档
- 核实结论（paddleocr.ai 官方文档）：PP-OCRv6 仅三档 tiny / small / medium(34.5M, 面向服务端)。"server" 是上一代 PP-OCRv5 的命名。用户要的"v6 服务端高精度模型"= 官方 **PP-OCRv6_medium**。
- 已将所有 server 命名回退为 medium：代码 `pp-ocrv6-medium` + `PP-OCRv6_medium_det.onnx`/`PP-OCRv6_medium_rec.onnx`；脚本 `get_ocr_models.sh v6-medium`；文档 `docs/deploy-linux.md`；计划文档 `docs/plans/ocr-v6-server-support.md`；HISTORY v5.0.21。
- 官方真实地址：HF `PaddlePaddle/PP-OCRv6_medium_det_onnx`、`PP-OCRv6_medium_rec_onnx`；ModelScope 同名；导出教程 `paddleocr.ai/.../obtaining_onnx_models.html`。
- 官方 medium 仓库内 onnx 文件名为 `inference.onnx`（det/rec 同名，分属不同仓库）。**用户选择：本地下载后统一按本仓库命名风格重命名**为 `PP-OCRv6_medium_det.onnx`/`PP-OCRv6_medium_rec.onnx` 放置（与 tiny 的 det_tiny/rec_tiny 风格一致）。代码/脚本/文档最终都按此统一命名，注释注明官方源文件名。
- 教训：涉及具体模型文件名/档位命名时，必须先查官方文档核实，不能猜测。

## Docker 构建修复：electron postinstall 下载失败
- 症状：`bun install` 时 electron postinstall 报 `RequestError: connect ECONNREFUSED 20.205.243.166:443`（GitHub 亚洲节点，国内网络被拒），Docker 构建中断。
- 根因：根 package.json devDependencies 含 `electron ^39.2.7`，`bun install --frozen-lockfile` 安装时其 postinstall 从 GitHub 下载桌面端二进制。
- 修复：`docker/Dockerfile` builder 阶段在 `BUN_CONFIG_REGISTRY` 后加 `ENV ELECTRON_SKIP_BINARY_DOWNLOAD=1`（服务端镜像不打包桌面端，electron 会在 `bun prune --production` 被移除；若需镜像内构建桌面端则改用 `ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/`）。
- ui/package.json 无 electron 依赖，不受影响。重新 `./docker/build.sh` 即可。
